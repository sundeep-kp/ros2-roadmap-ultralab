## Calling our first service

As stated earlier, Services are one-time requests that should perform a one-time action, and the result of that action is returned as a response.

In this case , we'll be calling a service to save an image from the camera.

First, we need to install the image_view package, which contains the image_save node which allows us to save images 
```
sudo apt-get install ros-humble-image-view
```

run the node-- 

```
ros2 run image_view image_saver --ros-args -p save_all_image:=false -r /image:=<camera_topic> -r /camera_info:=<camera_info_topic>
```

-r = Remap

-p = Parameter

we need to provide two topics , one for /image (like we did earlier to "/oak/rgb/color")

another for /camera_info which ontains information about camera parameters such as resolution or data for image calibration. Which using ros2 topic list I found to be */oak/
stereo/camera_info*

therefore, command becomes 
```
ros2 run image_view image_saver --ros-args -p save_all_image:=false -r /image:=/oak/rgb/color -r /camera_info:=/oak/stereo/camera_info

```
> yeah its stereo/camera_info instead of the plain camera_info for some reason.

At this point, the image_saver node is already running 
and waiting for the /save service to be called.

to call save service --

```
ros2 service call /save std_srvs/srv/Empty {}
```


![service](https://docs.ros.org/en/humble/_images/Service-SingleServiceClient.gif)



Here we are making a request call to the /save service which in turn asks the image save node to do its job and it in turn gives us the image as response through the /save service.

The image should be saved to whichever directory you ran the command from. In my case its ros2ws/

## "std_srvs/srv/empty.hpp"

std_srvs::srv::Empty. This is a built-in ROS 2 service type whose request and response contain no data fields at all. It is commonly used when you just want to trigger the service .
