## client_ = create_client<std_srvs::srv::Empty>("/save");
GPT-- 

Let's dissect it piece by piece:

```cpp
client_ = create_client<std_srvs::srv::Empty>("/save");
```

---
**1. `create_client`**

This is a member function of `rclcpp::Node`.

```cpp
create_client<ServiceType>(service_name)
```

It creates a **service client** that can call a service.

Think of it like:

```text
Publisher  -> sends messages to a topic
Subscriber <- receives messages from a topic

Client     -> sends requests to a service
Server     <- handles requests and sends responses
```

---

 **3.** `("/save")`

This is the **service name**.

```cpp
"/save"
```

ROS 2 will look for a service server advertising:

```text
/save
```

For example another node might have:

```cpp
server_ = create_service<std_srvs::srv::Empty>(
    "/save",
    callback
);
```

Then your client can connect to it. In our case its the image save node

---

### 4. What is returned?

`create_client()` returns:

```cpp
rclcpp::Client<std_srvs::srv::Empty>::SharedPtr
```

which is a smart pointer to a client object.

## How we are calling the service


Basically similar to how we manually sent a request to the service in [here](7.%20Timer%20+%20save.md)--


```
ros2 service call /save std_srvs/srv/Empty {}
```

We simply, create a request
```
auto request = std::make_shared<std_srvs::srv::Empty::Request>();
```
 and send it
 ```
  auto future = client_->async_send_request(request);
 ```

In other projects, 'future' will actually hold the response ,

However for the save service, the response is empty as well. (The image processing is handeled by the separate image saver node that we installed earlier)

Now the image counter part:-

with this
```
 server_ = create_service<std_srvs::srv::Trigger>("/image_counter", std::bind(&MyNode::counter_callback,this)); 
 ```
 we are creating a service that can respond with the no. of images saved upon request.

 The actual counting will be done in the image_callback function (since it runs each time an image is to be saved)

btw this is how the trigger service works -- https://docs.ros.org/en/api/std_srvs/html/srv/Trigger.html
